# OJT 작성 도우미

하루 동안 어떤 프로그램에서 무엇을 했는지 로컬에 기록해 두었다가, 그것을 업무 단위로
묶어 데일리 OJT 일지 초안으로 만들어 주는 로컬 프로그램입니다. 완성된 초안은 노션 표에
그대로 붙여넣을 수 있는 형식으로 나옵니다.

키 입력·비밀번호·클립보드·화면 이미지는 수집하지 않으며, 기록은 이 노트북을 벗어나지
않습니다.

## 실행

`start.bat`을 더블클릭하면 브라우저에서 `http://127.0.0.1:8765`가 열립니다.

다른 PC에 새로 설치할 때는 먼저 의존성을 설치합니다.

```sh
python -m pip install -r requirements.txt
```

## 미니 창

바탕화면의 `OJT 미니 도우미`를 실행하면 브라우저가 아닌 **340×520 크기의 Windows 프로그램
창**이 현재 마우스가 있는 화면 오른쪽 위에 열립니다. 전체 화면의 `미니 프로그램` 버튼으로도
같은 창이 열립니다. 두 번 실행해도 창은 하나만 유지되고 기존 창이 앞으로 나옵니다.

- **상단바가 따로 없습니다.** 메신저 앱처럼 앱 헤더가 그대로 제목 표시줄 역할을 하며,
  헤더의 빈 곳을 끌어 창을 옮깁니다. 오른쪽에 최소화(`–`)와 닫기(`×`)가 있습니다.
- 최소화하면 작업 표시줄로 들어가고, 거기서 다시 불러올 수 있습니다.
- `⌖` — **항상 위 고정을 켜고 끕니다.** 켜면 다른 창 위에 머물고, 끄면 뒤로 보낼 수
  있습니다. 기본값은 켜짐이며 선택은 자동 저장됩니다.
- `◐` — 투명도 패널이 헤더 아래에서 미끄러져 나옵니다. 45~100%를 실시간으로 조절하고
  슬라이더 위에서 휠로 미세 조정할 수 있습니다. 이 값도 자동 저장됩니다.
- 창 크기는 340×520으로 고정입니다.

### 단축키

| 키 | 동작 |
| --- | --- |
| `Ctrl` + `Enter` | 선택한 업무로 OJT 생성 |
| `Esc` | 투명도 패널 닫기 |
| 날짜 칸에서 `Enter` | 해당 날짜의 기록 상태 다시 확인 |

업무 후보 카드는 체크박스뿐 아니라 **카드의 빈 곳을 눌러도 선택**됩니다. 제목과 설명 칸은
그 자리에서 바로 고칠 수 있습니다.

## 업무 활동 모니터링

- Windows 로그인 후 모니터가 백그라운드에서 자동 실행됩니다.
- 15초마다 활성 프로그램명, 창 제목, 사용 시간을 `data/activity.db`에 로컬 저장합니다.
- 마우스로 누른 버튼·메뉴·탭의 접근성 이름과 상위 메뉴도 함께 기록합니다.
- 창 제목과 클릭된 UI 이름은 Windows DPAPI로 암호화되어 **같은 Windows 사용자 계정에서만**
  복호화됩니다.
- 5분 이상 입력이 없으면 자리 비움으로 보고 기록하지 않습니다.
- 시크릿·InPrivate 창은 기록하지 않습니다.
- **키 입력, 입력한 문장, 비밀번호, 클립보드, 화면 이미지와 영상은 수집하지 않습니다.**
- 작업표시줄·트레이·시작메뉴 클릭은 앞에 떠 있던 다른 프로그램의 업무로 잘못 기록되므로
  제외합니다.
- 메신저는 창 제목이 대화 상대 이름이라 프로그램 이름만 기록합니다.
- 프로그램이 접근성 이름을 제공하지 않는 자체 제작 화면(예: Acorn의 PowerBuilder 화면)에서는
  버튼명이 기록되지 않아 후보가 `작업 진행` 수준으로만 나옵니다.
- 모니터링 원본은 60일이 지나면 자동 삭제됩니다. 작성한 OJT 기록은 삭제되지 않습니다.
- VS Code 같은 개발 도구는 후보에서 제외됩니다. 포함하려면 `server.py`의
  `IGNORED_PROCESSES`에서 해당 줄을 지웁니다.

## 기록 정리

`기록 정리`를 누르면 같은 프로그램·화면에서 이어진 기록을 업무 단위로 묶습니다.

- 묶는 작업은 **규칙으로 먼저 끝냅니다.** 로컬 AI가 느리거나 실패해도 후보는 나옵니다.
- 로컬 AI는 각 단위의 **제목과 한 문장 설명**을 씁니다. `조회(3회) 클릭함` 같은 조작 묘사
  대신 `어느 화면에서 무엇을 했는지`를 업무 문장으로 적습니다.
- 기록에 등장한 프로그램명·화면 이름·조작한 항목 이름만 사용하며, 목적이나 결과는
  지어내지 않습니다.

### 후보에서 걸러내는 것

접근성 이름에는 업무와 무관한 값이 섞여 들어옵니다. 아래는 후보를 만들 때 제외합니다.

- 창 제목을 그대로 되읽은 이름
- 페이지 본문이 통째로 잡힌 긴 문자열(40자 초과)
- 숫자 배지(`3`, `99+`)처럼 글자가 거의 없는 값
- `메모리 사용량 - 369MB` 같은 상태 표시
- `닫기`, `홈`, `새 탭`, `뒤로` 같은 브라우저 껍데기 버튼
- 클릭 없이 2분도 머무르지 않고 스쳐 지나간 창

### 순서와 업무/개인 구분

- 후보는 **클릭 수가 아니라 실제로 붙잡고 있던 시간과 조작의 가짓수**로 정렬합니다.
  클릭 수로 줄세우면 잡다한 브라우징이 위로 올라옵니다.
- 로컬 AI가 각 후보를 업무인지 개인 활동인지 판단하고, 헬스·칼로리·길찾기·쇼핑처럼
  분명한 개인 도메인은 규칙으로 다시 확정합니다.
- 개인 활동도 지우지 않고 `개인` 표시를 달아 목록 아래쪽에 둡니다. 필요하면 선택할 수
  있습니다.

한 번 정리한 결과는 저장되어 다시 누르면 즉시 표시됩니다. 새로 만들려면 `↻`(다시 정리)를
누릅니다.

## OJT 초안 생성

원하는 후보만 선택하고 `OJT 생성`을 누르면 **선택한 항목만** 수행 업무에 반영됩니다.
후보에 없는 내용은 아래 추가 메모 칸에 적습니다.

초안은 노션 표에 그대로 붙여넣을 수 있는 형식으로 나옵니다.

```text
1. 업무 이름
• 그 업무에서 실제로 한 일
• 확인하거나 파악한 내용
2. 다음 업무 이름
• 그 업무에서 실제로 한 일
```

- 선택한 업무 하나가 소제목 하나가 됩니다.
- 건수·용량·기간처럼 메모에 적은 수치는 그대로 살립니다.
- 모델이 업무를 빠뜨리면 **후처리에서 빠진 항목을 뒤에 채워 넣고 번호를 다시 매깁니다.**
  일지에 올릴 기록이라 선택한 업무가 조용히 사라지지 않도록 한 장치입니다.
- 메모에 어려움·오류·장애·실패·부족이 적혀 있으면 이슈 항목으로 분리하고, 없으면
  `특이사항 없음`으로 둡니다.

`노션용 복사`를 누른 뒤 노션 표의 첫 번째 셀에 붙여넣습니다. 한 행 붙여넣기가 표 구조와
맞지 않으면 전체 화면에서 각 항목의 개별 복사 버튼을 사용합니다.

생성된 초안은 저장 전에 직접 고칠 수 있습니다. 로컬 모델이 가끔 오타나 메모에 없는 수식을
덧붙이므로 **저장 전에 한 번 훑어보는 것을 전제로 합니다.**

## 비용 없는 로컬 AI

Ollama와 `qwen3:4b-instruct` 모델이 설치되어 있으면 앱이 자동으로 감지합니다.

- 모델은 이 노트북에서 실행되며 업무 메모가 외부 AI 서버로 전송되지 않습니다.
- 용량이 큰 모델 파일은 `F:\OllamaModels`에 저장됩니다.
- Ollama가 꺼져 있으면 실행 시 백그라운드에서 자동으로 시작합니다.
- 토큰당 사용료는 없지만 최초 모델 다운로드 용량과 노트북의 CPU·메모리를 사용합니다.
- 화면 상단에 `로컬 AI · 비용 0원`이 표시되면 정상 연결된 상태입니다.
- 로컬 AI를 쓸 수 없으면 별도 계정 없이 동작하는 `로컬 규칙 모드`로 내려갑니다. 이때는
  선택한 후보의 제목과 설명을 그대로 옮긴 최소 형태가 나옵니다.

정리와 생성에는 각각 1~3분 정도 걸립니다. 진행 중에는 헤더 아래에 얇은 막대가 움직입니다.

## OpenAI 연결(선택)

1. `.env.example`을 복사해 `.env`라는 이름으로 저장합니다.
2. `OPENAI_API_KEY`에 본인의 OpenAI API 키를 입력합니다.
3. 프로그램을 다시 실행합니다.

`OPENAI_MODEL` 기본값은 예시이므로 본인 계정에서 실제로 사용할 수 있는 모델명으로 바꿔야
합니다. 로컬 AI를 사용할 수 없을 때만 OpenAI를 사용합니다. API 키는 브라우저에 전달하거나
저장하지 않습니다.

> 회사 업무 내용을 외부 API로 전송하기 전에 회사의 보안 정책을 확인하세요.

## 데이터 보호

- 회사 계정 비밀번호는 이 프로그램에 입력하거나 저장하지 않습니다.
- 노션 API 권한을 사용하지 않습니다.
- 모니터링 원본과 작성 기록은 `data/activity.db`에만 보관되며 저장소에 올라가지 않습니다
  (`.gitignore`).
- 로컬 서버는 화면 구성 파일만 응답합니다. `.env`, 소스 코드, 데이터베이스 파일은 주소로
  열리지 않습니다.
- 다른 노트북으로 옮기거나 초기화에 대비하려면 `백업 내려받기`를 정기적으로 사용하세요.

## 구성

| 파일 | 역할 |
| --- | --- |
| `server.py` | 로컬 HTTP 서버, 활동 모니터, 기록 묶기, 로컬 AI 호출, 암호화 저장 |
| `app.js` / `index.html` / `styles.css` | 전체 작성 화면(브라우저) |
| `mini_app.py` | CustomTkinter 기반 미니 창 |
| `mini_launcher.py` | 서버 기동 확인과 창 위치 계산 |
| `launch-mini.vbs` | 콘솔 없이 미니 창을 띄우는 실행기 |
| `install-mini-shortcut.vbs` | 바탕화면 바로가기 생성 |
| `data/` | 암호화된 활동·작성 기록 (저장소 제외) |
